# クォータ通知

アカウントのセッションクォータが不足したとき、回復したとき、全回復したときにデスクトップ通知でお知らせします。

![クォータ通知のアイコン](assets/icon.png)

## 機能

- 設定画面だけに表示され、スイッチの変更をすぐに保存します。
- 通知のしきい値を設定でき、クォータが回復するまでプロバイダーとアカウントごとに一度だけ通知します。
- デスクトップ通知に手動テストボタンがあります。
- インターフェースと README は英語、中国語（簡体字・繁体字）、韓国語、日本語、ブラジルポルトガル語に対応しています。

## 互換性

バージョン 0.1.0 は現在の実験的 `tmApi: 1` ホストと、同梱する表示データの修正を対象とします。ビルドと検証のコマンドは [MAINTAINING.md](MAINTAINING.md) を参照してください。

対象を絞った自動テストで、しきい値判定、設定、模擬通知、パッケージの整合性を確認しています。**最終的なネイティブ画面と実際の通知到達は未検証です。** 開発テストではデスクトップ通知の失敗が報告されています。Windows、Linux、パッケージ版ホストも未検証です。

既存のクォータデータを使用し、プロバイダーへの追加リクエストは行いません。欠落または古いデータをゼロとして扱いません。ホームカード、独立したページ、ウィンドウ全体の点滅はありません。

## インストール

この任意の公式プラグインが同梱された App で、**設定 → プラグイン → 探索**を開き、Token Monitor 公式グループの**クォータ通知**から**インストールして有効化**を選びます。**インストールのみ**を選ぶと無効のままになります。初回のバックグラウンド実行の提案を確認してください。プラグイン全体のスイッチとセーフモードは引き続き適用されます。

カタログ URL の追加は不要です。設定 → プラグインから `quota-alerts-0.1.0.tmplugin` または完全なソースフォルダーを取り込むこともできます。ローカルから取り込んだものはローカルの配布元として表示され、公式表示は App 同梱パッケージに適用されます。

## 使い方

1. プラグイン設定で**クォータ不足の通知**を有効にし、残量のしきい値を設定します。例：10%。
2. 必要に応じて**クォータ回復・全回復の通知**を有効にします。新しい値がしきい値未満からしきい値以上に戻ると回復通知、100% 未満から正確に 100% に戻ると全回復通知を送ります。同じ全回復で回復通知を重複して送りません。
3. **デスクトップ通知をテスト**で送信を確認します。テストであることを明示した実際の通知を送信します。クォータの値や重複通知の防止記録は変更しません。 自動通知のスイッチが両方オフでもテストできます。
4. 設定画面を閉じても通知を受け取るには、プラグイン管理でバックグラウンド実行を許可します。App は初回設定で提案しますが、拒否したり後から変更したりできます。Token Monitor は起動したままにしてください。

両方の通知は初期状態では無効で、個別に選択できます。初回の値、ソース変更後、バックエンド再起動後は通知せず回復の基準を作ります。すでに全回復している場合や 100% が続く場合は通知しません。リセットのカウントダウン終了だけでは回復と判断しません。

スイッチはすぐに保存されます。しきい値は入力欄からフォーカスを外すか Enter を押すと保存されます。保存に失敗した場合は確定済みの値に戻し、メッセージを表示します。

低クォータが続いても、回復するまでは繰り返し通知しません。App の再起動やデータソースの識別情報の変更で、新たな通知が発生する場合があります。送信失敗の自動再試行はありません。

以下は fixture データから生成した通知文の例で、OS のスクリーンショットではありません：

```text
Codex の残量不足
Session: 残り 7%
```

```text
Codex のクォータが全回復
Session: 残り 100%
```

## データとアクセス権限

プラグインはローカルユーザーの権限で実行される信頼済みコードです。このプラグインは取得済みのクォータデータと App の言語設定を読みます。プロバイダーの認証情報の読み取りや追加の問い合わせは行いません。設定と通知履歴は App が管理するプラグインデータディレクトリに保存します。

デスクトップ通知はホストの通知操作を使用します。このプラグインはネットワークリクエストを直接送信しません。

## 更新

公式パッケージは App とともに更新されます。変更後のプラグインコードを実行する前に内容を確認して承認してください。有効化、設定、確認済みのバックグラウンド実行の選択は引き続きユーザーが管理します。ロールバックはコードを戻すだけで、送信済みの通知は取り消せません。
