Plugin development guide

Build a same-page interface with an optional local Node backend. The plugin API is experimental and may change.

First manifest

Save this as manifest.json and add ui.mjs. Import the folder, enable the trusted revision, then choose Home.

Optional defaultSurfaces suggests initial locations. Confirm or change them at installation; install-only defers them until first enable. Updates preserve your choices. Full locations are skipped, and surface master switches stay unchanged.

Same-page interface

Author modules use DOM/CSS/JS inside the host renderer. Bundle your CSS and use native content nodes or helpers where available. The UI has no Node integration.

Data and settings

Use ctx.data.query/subscribe for captured App usage, limits and sessions. A versioned settings schema provides a host form; a settings view can provide custom controls. An optional Node backend handles files, network and computation, with one process shared across locations. It stops when no visible demand, pending call or explicitly enabled background work remains.

Test and distribute

Prebundle dependencies; installation never runs npm scripts. Test with synthetic data: idle, multiple surfaces, source changes, updates, native fallback and safe mode. Package with scripts/build-plugin-package.js. Native addons need target-platform and packaged verification.

Trust before enabling

Plugins can read local files and credentials, use the network, change data or freeze the interface. Enable only code you trust. A hash is not a security audit.

第一份宣告檔

儲存為 manifest.json 並新增 ui.mjs。匯入資料夾、確認首次顯示位置，再信任並啟用。

defaultSurfaces 可建議首次顯示位置。安裝時可確認或修改；只安裝會留待首次啟用才套用。更新保留用戶選擇，位置已滿會略過，亦不會更改顯示區域的總開關。

同頁介面

作者可在宿主 renderer 以 DOM／CSS／JS 設計介面。請將 CSS 打包，並按需要使用原生內容節點或 helpers。UI 沒有 Node 整合。

依賴須預先打包，安裝不執行 npm scripts。用合成資料測試閒置、多位置、來源變更、更新、原生回復及安全模式。以 scripts/build-plugin-package.js 打包；原生 addon 需在目標平台及封裝版本驗證。

信任後才啟用

外掛可能讀取本機檔案與憑證、連線、更改資料或令介面停止回應。只啟用你信任的程式碼；雜湊不代表安全審核。

플러그인 개발 가이드

같은 페이지의 UI와 선택적 로컬 Node 백엔드를 만들 수 있습니다. 플러그인 API는 실험적이며 변경될 수 있습니다.

첫 매니페스트

manifest.json으로 저장하고 ui.mjs를 추가하세요. 폴더를 가져오고 초기 위치를 확인한 다음 신뢰하고 활성화하세요.

defaultSurfaces로 초기 표시 위치를 제안할 수 있습니다. 설치 시 확인하거나 변경하며, 설치만 한 경우 첫 활성화 시 적용합니다. 업데이트는 사용자 선택을 유지합니다. 가득 찬 위치는 건너뛰며 전체 스위치는 변경하지 않습니다.

같은 페이지 UI

호스트 렌더러에서 DOM/CSS/JS로 UI를 디자인합니다. CSS를 번들에 포함하고 제공되는 네이티브 콘텐츠 노드나 helpers를 활용하세요. UI에는 Node 통합이 없습니다.

데이터와 설정

ctx.data.query/subscribe로 앱이 수집한 사용량, 한도와 세션을 읽습니다. 버전이 있는 설정 schema는 기본 폼을, settings view는 사용자 정의 UI를 제공합니다. 선택적 Node 백엔드는 파일, 네트워크, 계산을 처리하며 여러 표시 위치가 한 프로세스를 공유합니다. 표시 수요, 대기 중인 호출, 명시적으로 활성화한 백그라운드 작업이 모두 없으면 중지합니다.

테스트와 배포

의존성을 미리 번들하세요. 설치는 npm scripts를 실행하지 않습니다. 합성 데이터로 유휴, 여러 위치, 소스 변경, 업데이트, 네이티브 복원 및 안전 모드를 검증하세요. scripts/build-plugin-package.js로 패키징하며 네이티브 addon은 대상 플랫폼 및 패키지 검증이 필요합니다.

신뢰 후 활성화

플러그인은 파일과 자격 증명, 네트워크에 접근하고 데이터를 변경하거나 UI를 멈출 수 있습니다. 신뢰하는 코드만 활성화하세요. 해시는 보안 검토가 아닙니다.

プラグイン開発ガイド

同一ページの UI と任意のローカル Node バックエンドを作成できます。プラグイン API は実験的で、今後変更される可能性があります。

最初のマニフェスト

manifest.json として保存し ui.mjs を追加します。フォルダーを取り込み、初回の表示位置を確認して、信頼して有効化します。

defaultSurfaces で初回の表示位置を提案できます。インストール時に確認・変更でき、インストールのみの場合は初回有効化時に適用します。更新ではユーザーの選択を維持します。満員の場所はスキップし、全体スイッチは変更しません。

同一ページの UI

ホストのレンダラー内で DOM/CSS/JS を使って UI を設計します。CSS を同梱し、提供されるネイティブの内容ノードや helpers を利用できます。UI に Node 統合はありません。

データと設定

ctx.data.query/subscribe で App が取得した使用量、上限、セッションを読み取ります。バージョン付き設定 schema は標準フォームを、settings view は独自 UI を提供します。任意の Node バックエンドがファイル、ネットワーク、計算を担当し、表示位置間で一つのプロセスを共有します。表示の需要、保留中の呼び出し、明示的に有効にしたバックグラウンド処理がすべてなくなると停止します。

テストと配布

依存関係は事前にバンドルし、インストールは npm scripts を実行しません。合成データでアイドル、複数位置、ソース変更、更新、ネイティブ復旧と安全モードを確認します。scripts/build-plugin-package.js で梱包し、ネイティブ addon は対象環境とパッケージ版で検証してください。

信頼してから有効化

プラグインはファイルや認証情報、ネットワークにアクセスし、データを変更したり UI を停止させる可能性があります。信頼するコードだけを有効にしてください。ハッシュは安全性の審査ではありません。

Guia de desenvolvimento de plugins

Crie uma interface na mesma página com backend Node local opcional. A API de plugins é experimental e pode mudar.

Primeiro manifesto

Salve como manifest.json e adicione ui.mjs. Importe a pasta, confirme os locais iniciais, confie e ative.

defaultSurfaces sugere locais iniciais. Confirme ou altere na instalação; instalar sem ativar adia a aplicação até a primeira ativação. Atualizações preservam suas escolhas. Locais cheios são ignorados e os controles gerais não mudam.

UI na mesma página

Crie a UI com DOM/CSS/JS no renderizador do app. Inclua o CSS no pacote e use os elementos nativos ou helpers disponíveis. A UI não tem integração com Node.

Dados e configurações

Use ctx.data.query/subscribe para ler uso, cotas e sessões já coletados pelo app. Um schema de configurações versionado fornece um formulário nativo; uma settings view permite controles próprios. O backend Node opcional trata arquivos, rede e cálculos, compartilhando um processo entre locais. Ele para quando não há demanda visível, chamada pendente nem trabalho em segundo plano explicitamente ativado.

Teste e distribua

Empacote dependências antes; a instalação não executa npm scripts. Teste dados sintéticos, inatividade, vários locais, mudanças de origem, atualizações, retorno nativo e modo seguro. Use scripts/build-plugin-package.js; addons nativos exigem verificação da plataforma e do app empacotado.

Confie antes de ativar

Plugins podem acessar arquivos, credenciais e rede, modificar dados ou travar a interface. Ative apenas código confiável. Um hash não é uma auditoria de segurança.
