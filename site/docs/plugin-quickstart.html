Design for hiding and reopening

Hidden Rich documents release subscriptions and may be frozen for quick reuse. Default idle retention is 30 seconds. Per-document retainMs accepts a nonnegative safe integer or "until-evicted"; global count/memory limits may evict earlier. Retention never grants background web work.

Persist important state with tm.storage and handle cold launch. Respect host theme/reduced motion, keyboard focus, allocated viewport and missing readings. Main, detached and surface documents have separate owners.

Build on the named slots

There is no host DOM, arbitrary IPC or Node access. Rich assets are package-local; use the fixed tm bridge. Follow the authored UI reference for target fields, theme context and lifecycle bounds. Page Studio demonstrates original pages; Business Studio demonstrates shared App data and settings.

A practical rendering choice

Start with a declarative stat, meter, rows or sparkline when host controls can express the idea. The App validates the component tree, draws it in its own theme, and can share one source sample across placements. Use Rich UI for layout, animation, canvas or local images that need HTML/CSS/JS. A Rich target names a packaged entry and assets; it still needs a declarative fallback. The tray remains a host bitmap. Enable each supported placement in the App after installation.

Treat Rich UI as a lifecycle, not a permanent page

On first open, wait for the bridge and a first snapshot. For the CPU example, the Rich sys.cpu payload is an envelope and its number is reading.value; the Worker’s tm.read('sys.cpu') is the raw number. On hide, unsubscribe and release visible demand. A retained document may resume quickly, but expiry, memory pressure, update, disabled plugin or revoked permission can remount it cold. Save meaningful drafts in tm.storage, clear stale content on privacy/source resets, and keep the declarative fallback useful if the document fails. See the Rich UI contract for targets and bridge details.

Use App data and settings

Ask for the data you use

Use tm.data.usage for usage/tools/models, or the matching tm.data.devices, sessions, projects, history, limits, subscriptions or status grant. The full identifiers all start with tm.data.. Legacy tm.usage and tm.pages do not authorize these queries.

tm.data.identities additionally permits available names/titles/paths and display identities. Host hidden-title preferences and source scope still apply. Credentials, transcripts and internal IPC are not exposed. The host remains authoritative; do not rescan tools, poll providers or request consent for each query.

Query and page a snapshot

Declare tm.data.usage to try this in Worker or Rich code. Inspect availability before displaying rows; use coverage for collection scope and cost completeness for unknown prices.

tm.data.subscribe(query, callback) returns an unsubscribe function and delivers page one in a snapshot event. Do not add a second initial query. On invalidate with reset:true, clear rows/cursors immediately and refetch; ordinary invalidation can preserve the active traversal. Restart on snapshotExpired or invalidCursor.

Session queries build an index in chunks and convert only the requested page, so collections above 5,000 sessions can be traversed with the same cursor API. The host owns consistency and resource protection; authors can choose incremental loading or a virtual list. Memory, work and snapshot lifetime remain bounded; other resources retain their collection limits. Handle budgetExceeded, rateLimited, scopeUnavailable and unavailable/denied results explicitly. See the data reference.

Preserve what the data means

Session parentId/parentClient link opaque session identities. A parent can be outside the page or retained dataset; do not invent its row. All-time remote session detail can be unavailable or partial.

Subscription derivations use the host’s captured reporting date and FX map for renewal dates, recorded payments and monthly equivalent. Top-up depletion forecasts additionally require tm.data.limits, unambiguous authorized account matching and usable balance data. Unknown/stale/denied forecasts remain unavailable. Recorded amounts are not proof of bank transactions; an estimate is not a promised renewal date.

Declare and save preferences

Add a settings schema to the manifest. The standard host form works even when execution is off; a Rich settings editor is optional.

Use tm.settings.onChange for committed updates, without overwriting dirty drafts. Preserve the original revision until save; a conflict needs an explicit reload choice. Settings are plugin preferences, not credentials, arbitrary App settings or display placements. See Business Studio for a complete subscription, pagination and settings flow.

Choose a resource, then present its limits

Ask for only the resources the view needs. A usage card can start with tm.data.usage; a session list additionally needs tm.data.sessions, and names or paths require tm.data.identities. Use one subscribed first page and follow its cursor for more rows. A page is not a total; aggregateCoverage describes the authorized collection, while availability and cost completeness describe what can be shown. Remote all-time session detail can be partial or unavailable, and a privacy/source reset invalidates old identities. Never turn unknown cost into $0.

Preferences are saved state

The host form works without running plugin code. A Rich editor should keep the revision from the moment editing began, show a save result, and offer reload if another editor saved first. Keep the unsaved draft on conflict. The settings schema is local and versioned; it is distinct from placement switches, credentials and private tm.storage. See the data and settings API for exact DTOs and bounds.

Test and distribute

Test the experience you ship

  • Import → preview → allow → enable → place → open.
  • Cold open, quick reopen, expiry, resize, reduced motion and keyboard interaction.
  • Missing data, denied grants, paging resets and settings conflicts.
  • Hide all consumers: demand should stop. Revoke/disable while open and while cached.
  • Update → approve new access → rollback → uninstall with data retention.

Use a disposable profile. Test each claimed platform/surface; local macOS evidence does not prove Windows/Linux, packaged delivery or physical Notch behavior. See validation guidance.

Keep distribution simple

No public submission backend, review service or automatic source enrollment is implied. Follow the catalog contract for URL rules, compatibility, limits and recovery.

A useful acceptance pass

Run the installed package through the journey a reader will take: import, inspect requested grants, allow, enable, place and open. Check an empty first reading, a real reading and a denied grant. Test hiding the last consumer, cold reopening after retention, keyboard focus and reduced motion. For data views, show partial coverage and unknown cost; for settings, create a genuine competing save and confirm the unsaved draft survives. Rebuild after every manifest or asset change, then install the exact new bytes. Record the App build, platform, surfaces and checks that actually ran.

What the catalog does and does not prove

A catalog points to HTTPS package bytes and their SHA-256. The digest catches changed bytes; it does not review code or establish the author’s identity. Readers choose and review a source, then confirm each installation or update. Community remains Unreviewed. Optional source key pinning serves people who need stronger source identity; there is no public submission or moderation service. See the distribution contract for exact catalog and recovery rules.

處理隱藏與重新開啟

隱藏的 Rich 文件會釋放訂閱，可暫時凍結以便重用。預設閒置保留 30 秒；每份文件的 retainMs 可為非負安全整數或 "until-evicted"，但全域數量／記憶體限制可提早移除。保留不授予背景網頁工作能力。

重要狀態請用 tm.storage 儲存，並處理冷啟動。尊重 App 主題、減少動態效果、鍵盤焦點、分配尺寸及缺少讀數。不同視窗與介面有獨立擁有者。

使用公開插槽與橋接

無法存取 App DOM、任意 IPC 或 Node。資產位於套件內，透過固定 tm 橋接互動。目標欄位、主題與生命週期見 UI 參考。Page Studio 展示原有頁面，Business Studio 展示共享資料與設定。

實際選擇繪製方式

若主程式控制項已能表達構想，先用宣告式數字、儀表、列表或折線。App 驗證元件樹、套用自身主題，並可在多個位置共享同一來源取樣。需要 HTML/CSS/JS 的版面、動畫、canvas 或本地圖片時，才用 Rich UI。Rich 目標指定封裝入口與資產，仍須提供宣告式後備畫面。系統匣維持由主程式繪製的點陣圖。安裝後仍要在 App 開啟每個支援位置。

把 Rich UI 視為會重啟的畫面

首次開啟先等 bridge 與第一份資料。CPU 範例的 Rich sys.cpu 是封套，數值在 reading.value；Worker 的 tm.read('sys.cpu') 則直接傳回數字。隱藏時取消訂閱並釋放可見需求。保留的文件可能快速恢復，但過期、記憶體壓力、更新、停用或撤銷權限可使它冷啟動。重要草稿要存入 tm.storage，來源或私隱重設時清除舊內容；文件失效時，宣告式後備仍應可用。目標與 bridge 細節見 Rich UI 合約。

使用 App 資料與設定

只要求需要的資料

用量／工具／模型要求 tm.data.usage；其他資源分別要求 tm.data.devices、tm.data.sessions、tm.data.projects、tm.data.history、tm.data.limits、tm.data.subscriptions 或 tm.data.status。舊有 tm.usage 與 tm.pages 不授權這些查詢。

tm.data.identities 另外允許可用的名稱、標題、路徑與顯示身分；仍受來源範圍及隱藏標題偏好限制。不公開憑證、對話內容或內部 IPC。App 是資料權威，不要重掃工具、輪詢提供者或每次查詢都要求同意。

查詢並逐頁讀取快照

宣告 tm.data.usage 後，可在 Worker 或 Rich 程式碼試用。顯示前先檢查 availability、coverage 與費用完整性。

tm.data.subscribe(query, callback) 回傳取消訂閱函式，首個 snapshot 已含第一頁，不要再發初始查詢。invalidate 的 reset:true 要立即清除列與游標再讀取；一般失效可保留進行中的遍歷。遇到 snapshotExpired／invalidCursor 時重新開始。

會話查詢分段建立索引，只轉換當頁資料；超過 5,000 筆會話也可沿用相同 cursor API 完整遍歷。宿主負責一致性及資源保護，作者可選擇按需載入或虛擬列表。記憶體、工作量及快照期限仍有上限，其他資源保留原有集合限制。請處理 budgetExceeded、rateLimited、scopeUnavailable 及不可用／拒絕狀態，詳見資料參考。

保留資料語意

工作階段 parentId／parentClient 使用不透明身分；父階段可在頁面或保留資料之外，不要虛構其資料列。遠端全期間細節可能不可用或只涵蓋部分資料。

訂閱衍生值採用 App 擷取的報表日期及匯率，提供續期、已記錄付款及每月等值。儲值耗盡預測另需 tm.data.limits、明確授權的帳戶匹配及可用餘額。未知、過期或拒絕的預測保持不可用；記錄金額不是銀行交易證明，預測也不是保證續期日期。

宣告與儲存偏好設定

在宣告檔加入 schema。標準表單在停用時仍可使用，Rich 編輯器只是選項。

tm.settings.onChange 提供已提交狀態，不應覆蓋未儲存草稿。保留開始編輯時的 revision，衝突時保留草稿並讓使用者明確重新載入。這些不是憑證、任意 App 設定或顯示位置。完整流程見 Business Studio。

選資源，再說明其限制

只申請畫面需要的資源。用量卡可從 tm.data.usage 開始；工作階段列表另需 tm.data.sessions，名稱或路徑需要 tm.data.identities。訂閱首頁一次，再用 cursor 讀取其他頁。單頁不等於總量；aggregateCoverage 描述獲授權的集合，availability 和費用完整度則說明可顯示的內容。遠端「全部」工作階段詳情可能局部或不可用；私隱或來源重設會使舊身分失效。未知費用不可當作 $0。

偏好設定是已儲存狀態

即使外掛程式未執行，主程式表單仍可用。Rich 編輯器應保留開始編輯時的 revision、顯示儲存結果，並在另一編輯器先儲存時提供重新載入選項。衝突時保留未儲存草稿。設定 schema 是本機且有版本，與位置開關、憑證及私人 tm.storage 分開。DTO 與限制見 資料及設定 API。

tm.settings.onChange는 저장 상태를 알립니다. 미저장 초안을 덮어쓰지 말고 편집 시작 revision을 유지하세요. 충돌 시 초안을 보존하고 명시적으로 다시 불러옵니다. 자격 증명, 임의 앱 설정이나 배치 저장소가 아닙니다. 전체 예제는 Business Studio에 있습니다.

화면에 필요한 리소스만 요청하세요. 사용량 카드에는 tm.data.usage를, 세션 목록에는 추가로 tm.data.sessions를, 이름이나 경로에는 tm.data.identities를 사용합니다. 첫 페이지는 한 번만 구독하고 커서로 다음 페이지를 읽으세요. 한 페이지는 전체가 아닙니다. aggregateCoverage는 허용된 컬렉션을, availability와 비용 완전성은 표시 가능한 내용을 설명합니다. 원격 전체 기간 세션 상세는 일부 또는 사용 불가일 수 있고, 개인 정보/출처 재설정 후 기존 ID는 유효하지 않습니다. 알 수 없는 비용을 $0으로 표시하지 마세요.

환경 설정은 저장된 상태

플러그인 코드가 멈춰도 호스트 양식은 동작합니다. Rich 편집기는 편집 시작 때의 revision을 유지하고 저장 결과를 보여주며, 다른 편집기가 먼저 저장한 경우 새로 불러오기를 제안해야 합니다. 충돌 때 저장하지 않은 초안을 보존하세요. 설정 스키마는 로컬이며 버전이 있고, 배치 스위치, 자격 증명, 개인 tm.storage와 별개입니다. 정확한 DTO와 제한은 데이터 및 설정 API에 있습니다.

表示方式の選び方

ホストの部品で足りるなら、宣言型の数値、メーター、行、スパークラインから始めます。アプリが部品ツリーを検証し、テーマに沿って描画し、複数の表示先で一つの取得値を共有できます。HTML/CSS/JS の配置、アニメーション、canvas、ローカル画像が必要なら Rich UI を使います。Rich の対象には同梱入口と資産を指定し、宣言型の代替表示も用意します。トレイはホスト描画のビットマップのままです。インストール後に各表示先をアプリで有効化してください。

Rich UI は再起動を前提にする

初回表示時はブリッジと最初のスナップショットを待ちます。CPU 例の Rich sys.cpu は包みで、数値は reading.value にあります。Worker の tm.read('sys.cpu') は数値そのものです。非表示時には購読を解除し、表示用の要求を解放します。保持文書は素早く戻ることがありますが、期限、メモリ、更新、無効化、権限取消で冷起動になります。重要な下書きは tm.storage に保存し、プライバシーや出典のリセット時には古い内容を消してください。文書が失敗しても宣言型の代替表示を役立てます。Rich UI 契約を参照してください。

アプリデータと設定を使う

必要なデータだけ要求する

使用量／ツール／モデルには tm.data.usage を使います。ほかに同じ tm.data. 接頭辞の devices、sessions、projects、history、limits、subscriptions、status があります。従来の tm.usage や tm.pages では許可されません。

tm.data.identities は取得可能な名前、タイトル、パスなどを追加で許可しますが、非表示設定とソース範囲は維持されます。認証情報、会話本文、内部 IPC は公開されません。ホストを正とし、再スキャン、プロバイダーのポーリング、クエリごとの同意要求をしないでください。

スナップショットをページングする

tm.data.usage を宣言して試せます。表示前に availability、coverage と費用の完全性を確認します。

tm.data.subscribe(query, callback) は解除関数を返し、最初の snapshot に一ページ目を含みます。初回 query を重複させません。reset:true の無効化では行とカーソルを直ちに消し、再取得します。通常の無効化は走査を維持できます。snapshotExpired／invalidCursor では最初からやり直します。

セッションクエリは段階的にインデックスを作り、要求されたページだけを変換します。5,000 件を超えるセッションも同じ cursor API で走査できます。一貫性とリソース保護はホストが担い、作者は必要に応じた読み込みや仮想リストを選べます。メモリ、処理量、スナップショットの有効期間には上限があり、他のリソースの集合上限は変わりません。budgetExceeded、rateLimited、scopeUnavailable、拒否／利用不可を処理してください。詳細はデータ仕様へ。

意味を保って表示する

セッションの parentId／parentClient は不透明な識別子です。親が現在のページや保持データにない場合、行を捏造しません。リモートの全期間セッション詳細は不完全な場合があります。

サブスクリプションの更新日、記録済み支払い、月額換算はホストの報告日と為替マップを使います。チャージ残高の枯渇予測には tm.data.limits、一意の許可済みアカウントと有効な残高が必要です。不明／古い／拒否の予測を数値にしません。記録は銀行決済の証明ではなく、予測は更新日の保証ではありません。

設定を宣言して保存する

マニフェストに schema を追加します。標準フォームは無効化中も使え、Rich エディターは任意です。

tm.settings.onChange は保存済み状態を通知します。未保存の入力を上書きせず、編集開始時の revision を保持し、競合は明示的な再読み込みで解決します。認証情報や任意のアプリ設定、配置のストアではありません。完全な実装は Business Studio にあります。

資料を選び、その限界を示す

画面に必要な資料だけを要求します。使用量カードは tm.data.usage、セッション一覧には追加で tm.data.sessions、名前やパスには tm.data.identities が必要です。最初のページを一度購読し、後続はカーソルで読みます。一ページは総量ではありません。aggregateCoverage は許可された集合、availability と費用の完全性は表示できる範囲を示します。遠隔の全期間セッション詳細は部分的または利用不能になり得ます。プライバシーや出典のリセットで古い ID は無効です。不明な費用を $0 にしないでください。

設定は保存済みの状態

プラグインコードが止まっていてもホストのフォームは使えます。Rich 編集画面は編集開始時の revision を保持し、保存結果を示し、別の編集画面が先に保存したら再読込を選べるようにします。競合時には未保存の下書きを残してください。設定スキーマはローカルで版を持ち、配置スイッチ、認証情報、個人用 tm.storage と別です。正確な DTO と制限はデータと設定 APIを参照してください。
