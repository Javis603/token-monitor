# Usage archive replay

The session archive retains complete observations by canonical client/session and period. A native observation, including a lower token count or explicit zero, replaces that identity's archived observation. Missing identities stay retained. Today/month observations apply only to their recorded local calendar window.

The client archive is a frozen per-client snapshot captured when tracking is disabled. It may carry sessions, but older or synchronized sources can retain only aggregate totals and model buckets. Client replay must not overwrite a native observation merely because the tracking selection changed: subtract the matched archived contribution by session identity, retain unmatched sessions and any identity-free remainder, then apply the residue. Token/model/cost amounts are removed from the archived snapshot, so fresh lower counts and zero prices remain authoritative. Never deduplicate different clients by bare session id.

Both replay paths classify explicit saved session `inputTokens` as known input, bounded by the session's remaining token budget after cache read/write and output. Cache writes remain a subset of the displayed uncached input; they are not added twice. Missing legacy input is not inferred from totals. Client-level input can remain exact for a multi-model session while model-level splits remain unknown; only a single-model session supports assigning its saved input to that model.

Aggregate-only client snapshots have no identity proof. Equal token totals, costs or model distributions are not a safe deduplication key. This replay correction deliberately does not discard or migrate those snapshots automatically. If they overlap retained sessions, resolving the legacy data needs an authoritative source rebuild or additional recorded provenance and a separately reviewed recovery operation. No archive file or SQLite schema migration is performed by this fix.

A source-rebuild audit is distinct from production replay: enabling a previously disabled client permits a fresh native scan to replace that client's frozen snapshot and retain missing session observations. A dry-run demonstrating recoverable components does not authorize deleting a snapshot, rewriting costs or dividing totals by two.

New scanner observations retain optional session `modelTokenComponents` before row-level attribution is lost during session aggregation. Both archive replay paths use these observed model components; legacy single-model replay remains supported. Missing multi-model evidence stays unclassified, including unobserved portions of a partially covered model bucket. SQLite stores this additive field in its existing JSON observations, without a database schema migration. A newer native observation still replaces the entire old session, including lower counts, removed models and explicit zeros; never copy old component evidence onto newer totals.

Existing legacy sessions gain this evidence only through a fresh authoritative native observation. This change does not rebuild deleted sources or mutate saved archives as a migration. Old anchors without the map cannot prove a watch delta; a completed full scan establishes new coverage. Do not claim historical per-model recovery solely from session-level component totals.
